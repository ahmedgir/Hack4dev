# Frontend — Discovery Webapp ثابتة على Vercel

## الحالة الحالية

بدأ التنفيذ الفعلي بـNext.js وTypeScript. الصفحة الأولى تعرض CoRoT-2 من ملفات
`outputs/` الحقيقية، مع صورة الحقل ومنحنى السطوع ومؤشر Timeline.

التشغيل المحلي:

```bash
pnpm install
pnpm dev
```

التحقق وإنتاج نسخة Vercel ثابتة:

```bash
pnpm validate:data
pnpm build
```

تعليمات إضافة الأنظمة موجودة في `webapp/ADDING_SYSTEMS.md`.

## الهدف

واجهة Guest عربية/إنجليزية تحول النتائج العلمية المحسوبة مسبقًا إلى رحلة سهلة، من صورة التلسكوب إلى الحكم على جلسة الرصد.

## حدود الـMVP

- لا تسجيل دخول.
- لا Dashboard إداري.
- لا رفع FITS.
- لا API حي.
- لا ML.
- لا 3D مخصص في النسخة الأولى؛ إن استُخدم رسم NASA فيجب وصفه بأنه توضيحي وليس رصدًا حقيقيًا.

## الصفحات

### `/`

- Hero بجملة واحدة واضحة.
- شرح مصور قصير لمسار الاكتشاف.
- زر «ابدأ بـCoRoT-2».
- Preview للأنظمة وحالات النتائج المختلفة.

### `/systems`

- قائمة الأنظمة الثمانية.
- اسم النجم والكوكب.
- عدد الجلسات المكتملة.
- أفضل حالة متاحة: واعدة أوليًا / غير كافية / غير متسقة / غير محللة.
- لا تعرض «احتمال وجود الكوكب»؛ الكواكب مؤكدة مسبقًا.

### `/systems/[slug]`

- بطاقة النظام: period، published depth، duration وRA/Dec.
- قائمة الجلسات وتغطيتها.
- اختيار جلسة للـExplorer.
- صياغة واضحة تفرق بين القيم المنشورة وقياساتنا.

### `/systems/[slug]/sessions/[date]`

- صورة الإطار مع دائرة على النجم المضيف.
- Timeline أو slider لكل الصور.
- منحنى ضوئي مرسوم من JSON ومتزامن مع الصورة.
- حالة الإطار وسبب رفضه عند الحاجة.
- تبويب مبسط: الصورة، القياس، الجودة، الحكم.
- مقارنة published مقابل measured.

## PNG أم رسم تفاعلي؟

### استخدم الصور المسبقة لـ

- الحقل المثبت وموضع النجم.
- Raw / calibrated comparison.
- معاينات Timeline.
- صور المشاركة الاجتماعية أو fallback.

### استخدم JSON للرسم لـ

- Light curve.
- expected model.
- accepted/rejected points.
- hover والتزامن بين الصورة والنقطة.

السبب: PNG سريع لكنه لا يسمح للمستخدم بفحص النقاط. JSON يعطينا التفاعل دون إعادة التحليل العلمي.

## قواعد اللغة العلمية

- قل «النجم المضيف»، لا «النجم الأقرب».
- قل «السطوع»، لا «لون النجم».
- قل «استعادة أولية لعبور معروف»، لا «اكتشفنا الكوكب».
- الدائرة تحدد موضع النجم من WCS والإحداثيات المنشورة.
- الإطار المرفوض لا يختفي؛ يظهر باهتًا مع السبب.
- استخدم labels بشرية مع الاحتفاظ بالقيمة التقنية للتفاصيل.

## حالات الحكم المقترحة للواجهة

- `promising_preliminary_transit` → «عبور أولي واعد».
- `insufficient_for_transit_claim` → «البيانات غير كافية للحكم».
- `transit_like_but_parameters_inconsistent` → «شكل يشبه العبور لكن المعاملات غير متسقة».
- `not_analysed` → «لم تكتمل المعالجة».

لا تحوّل الحالات إلى نسبة مئوية؛ ذلك يوحي باحتمال علمي لم نحسبه.

## الأداء على Vercel

- اجعل الصفحات ثابتة قدر الإمكان.
- حمّل بيانات النظام المختار فقط.
- استخدم WebP للـTimeline وlazy loading للإطارات التالية.
- لا تحمل صور جلسات الأنظمة الثمانية في الصفحة الأولى.
- يمكن preload لإطار واحد قبل والمؤشر الحالي وإطار واحد بعده.
- استخدم صورة fallback إذا فشل تحميل إطار Timeline، ولا تخفِ نقطة القياس.

## Definition of Done للهاكثون

- مستخدم غير متخصص يفهم أننا لا نرى الكوكب مباشرة.
- يستطيع تحديد النجم المضيف ومعرفة كيف حُدد.
- يحرك Timeline ويرى النقطة المقابلة على المنحنى.
- يرى إطارًا مرفوضًا ويفهم سبب رفضه.
- يميز القيم المنشورة عن نتائج جلستنا.
- يرى حكمًا صريحًا بلا مبالغة.
- تعمل التجربة على الهاتف والحاسوب ضمن نشر Vercel ثابت.
