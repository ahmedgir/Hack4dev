# Hack4Dev Webapp — ملخص التنفيذ الثابت

هذا الملف هو المرجع القصير الذي نعود إليه قبل أي عمل على الموقع. الهدف منه منع إعادة النقاش وتوفير الوقت والتوكنز.

## القرار النهائي للهاكثون

- الموقع Guest فقط، بلا حسابات أو تسجيل دخول.
- الاستضافة على Vercel المجاني.
- لا يوجد Backend حي في النسخة الأولى، ولا نحتاج FastAPI الآن.
- الـPython pipeline يعمل محليًا قبل النشر ويصدر ملفات صغيرة جاهزة للموقع.
- الواجهة تقرأ JSON وتعرض صور WebP/PNG ورسومًا تفاعلية.
- لا تُرفع ملفات FITS الخام إلى Vercel ولا تُحلل داخل المتصفح.
- لا توجد قاعدة بيانات في الـMVP.

## جملة المنتج

أداة عربية/إنجليزية تشرح كيف تتحول صور تلسكوب حقيقية إلى قياس لسطوع نجم مضيف، وكيف نقارن الانخفاض المتوقع بعبور كوكب معروف مع إظهار جودة البيانات وحدود النتيجة.

## ما الذي ندّعيه؟

- لا نعرض صورة الكوكب؛ الدائرة تشير إلى النجم المضيف.
- الأنظمة في البيانات تحتوي كواكب مؤكدة مسبقًا؛ لا نعرض «احتمال وجود الكوكب».
- نعرض قوة نتيجة جلسة الرصد: واعدة أوليًا، غير كافية، أو معاملات غير متسقة.
- CoRoT-2 استعادة أولية واعدة لعبور معروف، وليست اكتشافًا جديدًا أو تأكيدًا مستقلًا.

## مسار البيانات

```text
Raw FITS (local only)
→ Python scientific pipeline
→ validated JSON + WebP/PNG
→ frontend/public/data + frontend/public/media
→ static Vercel deployment
```

## قرار الصور والرسوم

استخدم صورًا محسوبة مسبقًا عندما تكون النتيجة صورة فعلًا:

- صورة الحقل وعليها موضع النجم ونجوم المقارنة.
- Raw مقابل Dark-corrected.
- معاينات كل إطار في الـTimeline بصيغة WebP.
- صور احتياطية وSocial preview.

لا تستخدم PNG كواجهة أساسية للـlight curve. اقرأ `web_light_curve.json` وارسم المنحنى في الواجهة، لأن المستخدم يحتاج hover وربط المؤشر بالصورة. يمكن الاحتفاظ بـ`02_light_curve.png` كنسخة احتياطية أو للتوثيق فقط.

## تجربة المستخدم المختصرة

1. Hero: الكوكب غير مرئي، لكن أثر عبوره على ضوء النجم قابل للقياس.
2. شرح مبسط: FITS → إزالة ضوضاء → WCS → النجم → السطوع → المنحنى.
3. قائمة الأنظمة الثمانية مع أفضل جلسة وحكمها.
4. صفحة النظام: معلومات النجم والكوكب والجلسات.
5. Explorer: صورة الإطار + Timeline + منحنى متزامن.
6. طبقة «لماذا نثق بهذه النقطة؟»: الجودة وسبب القبول/الرفض.
7. مقارنة المنشور بالمقاس، ثم حكم علمي صريح.

## ترتيب التنفيذ

1. اتفق على wireframe واحد لصفحة CoRoT-2.
2. جهّز عقد البيانات النهائي للواجهة.
3. صدّر جلسة CoRoT-2 كاملة إلى مجلد الويب.
4. ابنِ صفحة النظام والـTimeline.
5. أضف حالة فشل واحدة: WASP-10 أو WASP-2.
6. أضف Qatar-1 لتوضيح أن شكل المنحنى وحده لا يكفي.
7. أضف بقية الأنظمة بعد ثبات القالب، لا قبل ذلك.
8. اختبر الفهم والأداء ثم انشر على Vercel.

## قاعدة منع التوسع

أي ميزة لا تساعد المستخدم على فهم الصورة أو القياس أو الحكم العلمي تؤجل لما بعد الهاكثون. لا حسابات، لا رفع ملفات، لا تحليل سحابي، لا ML، ولا لوحة إدارة.
